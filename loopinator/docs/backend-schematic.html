CONTEXT.md is a glossary, not a Prisma schema. These are the records the Play payload and Editor writes have to persist once Turso grows past Better Auth.

RecordHeld whereWho sees itNotes from CONTEXT.md
Track Turso row + Blob file Editor: full row. Musician: Play payload only. Track name, Filename, Original BPM, Key, Time signature, Loop region, Short id, soft-delete flag, Auto-detected flags.
Setlist Turso Editor: list. Musician: only the linked one. Name, Short id, ordered slots. Same Track may occupy more than one slot.
Setlist slot Turso, owned by Setlist Anyone who can open that Setlist. Copies Loop region, Target BPM, Transport fade, Key, Time signature. Track name stays on the Track. Slot label sticks.
Play payload DTO from Turso, not a table Anyone with the Short id. Addressed Track or Setlist plus Play screen fields. Omits Filename and Library-only fields.
User / Session / Account Turso, Better Auth Signed-in Editor Shipped. Every signed-in account is an Editor. No read-only tier.
Invite code Env, not a row Nobody. Sign-up checks it. One church-wide secret. Google, Apple, and email all require it.
Local override This browser This device Read first, then slot, then Track default. Save for everyone is the cloud write.
Offline cache This browser This device Metadata and audio. Expires 30 days after last open. Missing audio is an Unavailable Track.
